本編フレームワーク集

コースの流れは コース全体 → 導入 → 本編 → 定着・締め。この本編＝「思考の流れ」そのもので、作り手が内容に沿って組み立てる中心部です。思考の流れを型にしたものがフレームワーク——それは頭の整理だけでなくスライドの見せ方そのものになります。フローが決まれば、既存のページ型（概念/手順/構造/比較/データ/失敗/まとめ…）と図解（ロジックツリー/なぜなぜ/Before-After…）を並べるだけで本編が1本組めます。

例 課題解決フレームFLAGSHIP · 添付資料の型

「思考の流れ＝スライド構成」の代表例。ロジックツリー → なぜなぜ分析 → Before/After の流れで、課題特定から解決効果までを論理的に説明する。上段＝思考の流れ、下段＝そのままスライドの並びになる。

目的：課題の全体像から本質原因を特定し、解決策とその効果を納得感をもって伝える。

思考の流れ（フレームワーク）
1現状把握▸ 2課題の分解▸ 3原因の深掘り▸ 4解決方針の設計▸ 5Before / After▸ 6実行
スライド構成（既存の型に落とす）
レッスン表紙› データ／問題提起› 構造：ロジックツリー› 構造：なぜなぜ分析› 比較／解決方針› ビフォーアフター› 手順：実行ステップ› まとめ
使う場面／伝えたいこと

場面：業務改善・品質改善・コスト削減などの課題解決／経営層・上司への報告・提案／改善活動の振り返り。　メッセージ：「なぜその課題に取り組むのか」「なぜその原因にたどり着いたのか」「なぜその解決策が効くのか」を論理で示し、納得と行動を生む。

C 本編フレームワークTEACH FLOWS · 12

本編で基本的に作る「思考の流れ」を12に整理（上の課題解決フレームを含む）。各フローは既存のページ型・図解を並べるだけで組める。青チップ＝主となる型／グレー＝補助。作り手はコース内容に応じて選び・増減する。TF1〜7＝汎用の中心、TF8〜12＝場面特化の拡張。

TF1課題解決型
課題特定 → 本質原因 → 解決策 → 効果 を論理的に。上のフラッグシップ。
思考の流れ
1現状▸2分解▸3原因▸4方針▸5効果
スライド構成
データ›ロジックツリー›なぜなぜ›解決方針›Before/After›手順
場面：業務改善・提案・振り返り
TF2概念習得型（What→Why→How）
新しい概念を「理解して使える」まで持っていく、最も基本の流れ。
思考の流れ
1概念とは▸2なぜ重要▸3構成要素▸4具体例▸5誤解
スライド構成
概念解説›動機づけ›構造：要素分解›具体例›よくある失敗›まとめ
場面：基礎概念の導入（IT/ビジネス基礎）
TF3手順習得型（How-to）
作業を「自分で再現できる」ようにする。操作・実務手順に。
思考の流れ
1全体像▸2ステップ分解▸3各詳細▸4落とし穴▸5実践
スライド構成
構造：全体フロー›手順›画像／UI解説›よくある失敗›ワーク
場面：ツール操作・実務手順（IT）
TF4フレームワーク適用型
3C・4P・SWOT等の分析フレームを、走る事例に当てはめて理解を繋ぐ。
思考の流れ
1フレーム紹介▸2各要素▸3事例に適用▸4示唆
スライド構成
概念：フレーム図›構造：各要素›具体例：事例適用›データ／比較›まとめ
場面：マーケ・戦略分析（走る事例を全編で反復）
TF5比較・意思決定型
選択肢から最適を選ぶ。評価軸で比べ、推奨と根拠を示す。
思考の流れ
1論点▸2選択肢▸3評価軸で比較▸4推奨
スライド構成
概念：論点›比較表›構造：マトリクス›データ›まとめ：推奨
場面：ツール選定・方針決定
TF6データ・示唆型（分析→結論）
データから結論を導く。問い→数字→読み取り→アクション。
思考の流れ
1問い▸2データ▸3読み取り▸4結論▸5行動
スライド構成
動機づけ：問い›データ：グラフ›データ＋示唆›まとめ›次のアクション
場面：効果測定・レポート・KPI報告
TF7語学・スキル型
フレーズ・構文を「使える」まで。提示→意味→例文→運用→練習。
思考の流れ
1フレーズ▸2意味/構文▸3例文▸4会話で運用▸5練習
スライド構成
例文・対訳›文法・構文›具体例›会話›ワーク
場面：語学・ビジネス会話
TF8ストーリー・事例型（ケーススタディ）
1つの事例を物語として追い、追体験から学ばせる。分析型(TF1)と違い「筋」で見せる。
思考の流れ
1背景設定▸2課題に直面▸3打ち手▸4結果▸5教訓
スライド構成
具体例：背景›よくある失敗：直面›手順：打ち手›Before/After：結果›まとめ：教訓
場面：成功／失敗事例・導入ストーリー・体験談
TF9原則・ルール型（ベストプラクティス）
守るべき原則を提示し、理由と適用例、やって良い/悪いで定着させる。
思考の流れ
1原則を提示▸2各原則の理由▸3適用例▸4DO&DON'T
スライド構成
概念：原則リスト›構造：各原則›具体例：適用›よくある失敗：DO/DON'T›まとめ
場面：ガイドライン・規約・作法・品質基準
TF10判断フロー型（選び方・トラブル対処）
「こういう時はこうする」を条件分岐で示す。状況→判断→対処の道筋を1枚に。
思考の流れ
1状況の分類▸2条件で分岐▸3判断▸4対処
スライド構成
概念：判断軸›構造：判断フロー›具体例›手順：対処›まとめ
場面：トラブルシュート・選び方・if-then の判断基準
TF11時系列・変遷型（歴史・ロードマップ）
過去から未来への流れで文脈を与える。「なぜ今そうなっているか」を時間軸で。
思考の流れ
1起点▸2転機▸3現在▸4展望
スライド構成
構造：タイムライン›具体例：転機›データ：現状›まとめ：ロードマップ
場面：技術・業界の変遷・沿革・今後の見通し
TF12分類・使い分け型（タクソノミー）
種類を分類軸で整理し、それぞれの特徴と使い分けを示す。「一覧して選べる」状態に。
思考の流れ
1全体像▸2分類軸▸3各タイプ▸4使い分け
スライド構成
概念：全体›構造：マトリクス／ツリー›比較：各タイプ›まとめ：使い分け
場面：種類の整理・ツール分類・型の一覧

相談メモ（この先どうするか）

① 各フローを「型」として実装：フレームワーク名を指定するだけで、上のスライド構成を一括で生成（例 【本編:課題解決】 → 6枚を自動配置）。content.txt に流し込む見出しだけ用意すれば1チャプター分が組める。

② 不足している図解ビルダー：課題解決フローには ロジックツリー と なぜなぜ分析 の専用図が要る（現状ツリーは実装済み・なぜなぜは派生で作れる）。

③ 粒度の相談：12で過不足ないか／さらに業種別の派生が要るか／各フローの枚数（4〜6枚）は妥当か。TF1〜7が中心、TF8〜12は場面特化。
