# 参考デザイン取り込みワークフロー（refs/）

外部のスライド/資料デザインを **集める → タグで整理する → テーマプリセットに“蒸留”する** ための仕組み。
Slideland（https://www.slideland.tech/ ）のような参考ギャラリーを、**自分の生成パイプラインに接続する形**で運用する。

## 位置づけ（3層のうちの ① と、③への橋渡し）

- **① 参考ギャラリー（ここ＝refs/）** … インスピレーションの引き出し。**そのまま実装しない**。方向性を決める材料。
- **② 実装ライブラリ** … `diagrams.py`（図解16型）・`pages.py`（ページ28型）。生成の本体。
- **③ テーマ／トークン層** … `brand.py` をテーマ辞書化した再配色の仕組み（今後）。**外部参考は presets/ 経由でここに反映する**。

> ⚠️ **著作権の線引き（必読）**
> - このボードは **社内閲覧専用**。`board.html`・`inbox/` の画像は **公開・共有・Artifact化しない**（他社資料の再配布に当たる）。
> - 参考から取り込んでよいのは **一般的な原則だけ**＝配色・書体ペア・余白リズム・レイアウトの“考え方”・グラフの装飾。
> - **NG**：他社スライドの丸ごと再現、ロゴ・写真・固有の作り込みレイアウトのコピー。
> - 出典URLは `refs.json` に必ず残す（内部トレース用）。

## フォルダ構成

```
refs/
├─ README.md              このファイル（運用ルール）
├─ refs.json              参考のメタデータ（1参考=1レコード）
├─ build_board.py         refs.json + inbox画像 → board.html を生成
├─ board.html             タグ絞り込みできる閲覧ボード（自動生成・社内専用）
├─ inbox/                 参考スクショ（*.png / *.jpg）を置く場所
├─ presets/              “蒸留”したテーマプリセット（*.md）。③テーマ層の素
└─ theme-preset.template.md  presets の雛形
```

## 使い方（4ステップ）

1. **集める**：良い参考のスクショを `inbox/` に保存（ファイル名は `20260826_saas-blue-cover.png` のように日付＋内容）。
2. **記録する**：`refs.json` に1レコード追記（下記スキーマ）。タグは「タグ語彙」から選ぶ。
3. **ボード更新**：`.venv/bin/python3 refs/build_board.py` を実行 → `board.html` を再生成。ブラウザで開き、タグで絞り込んで眺める。
4. **蒸留する**：採用したい参考は `theme-preset.template.md` をコピーして `presets/<名前>.md` を作り、**配色・書体・余白・モチーフだけ**を書き出す。`refs.json` の該当レコードの `extract` を `"done"`・`preset` にパスを記入。

## refs.json スキーマ（1レコード）

```json
{
  "id": "saas-blue-cover",
  "title": "SaaS会社紹介 表紙（青・信頼感）",
  "file": "20260826_saas-blue-cover.png",   // inbox/ 内のファイル名（無ければ "" ）
  "source": "https://…",                     // 出典URL（必須）
  "captured": "2026-08-26",
  "doc_type": "会社紹介",                    // 資料の種類（タグ語彙参照）
  "industry": "SaaS",                        // 業種
  "colors": ["ブルー", "ネイビー"],          // 配色（複数可）
  "taste": ["信頼感", "ミニマル"],           // テイスト（複数可）
  "element": ["表紙"],                        // ページ/要素タイプ（複数可）
  "notes": "余白広め・大見出し1つ・図は右下に小さく。",
  "extract": "todo",                         // "todo" | "done"
  "preset": ""                                // 蒸留したら presets/xxx.md
}
```

## タグ語彙（Slideland軸をコース用に翻訳）

- **doc_type（資料の種類）**：コース表紙 / チャプター扉 / 概念 / 手順 / 比較 / データ / 演習 / まとめ / 会社紹介 / サービス紹介 / 事業計画 / 登壇資料
- **industry（業種）**：IT / SaaS / AI / 金融 / 製造 / 物流 / 教育 / 人材 / マーケティング / 不動産 / その他
- **colors（配色）**：ブルー / ネイビー / グリーン / オレンジ / パープル / ピンク / イエロー / ライトブルー / ブラック / ツートン / カラフル
- **taste（テイスト）**：ミニマル / 信頼感 / スタイリッシュ / 爽やか / ポップ / やさしい / 高級感 / ダイナミック / 近未来
- **element（要素タイプ）**：表紙 / グラフ / 図解 / イラスト / 写真 / 本文レイアウト / 締め

> 実装ライブラリ（diagrams.py / pages.py）側の型にも将来この語彙でタグを付けると、
> 「IT・手順・信頼感」で参考と自作型を横断検索できる（Slidelandの閲覧体験の自分版）。

## Slideland等を見るときの観察の観点（今後の運用）

更新される参考スライドを定期的に見て、**デザインの“見方”を一定の観点で観察**し、スクショを `inbox/` に貯める。狙いは「スライド・パターンライブラリ」「コース用スライド型テンプレ」を、**自作のオリジナルとして**磨くこと（特定スライドの複製ではない）。

観察してメモする観点（`refs.json` の `notes` に記録）:
- **レイアウト構成**：要素の置き方・グリッド・非対称/対称・視線の流れ
- **配色バランス**：主色/背景/アクセントの比率、どこに色を効かせているか
- **アイコンの置き方**：サイズ・位置・面で塗るか線か・余白の取り方
- **写真の置き方**：全幅/半分/切り抜き、テキストとの重ね方、トリミング
- **文字の位置と大きさ**：見出し/本文/キャプションの比率、寄せ、行間、余白

⚠️ **反映は原則だけ**：観察で得た「型・比率・置き方」を**自分のブランドで再設計**して `diagrams.py`/`pages.py`・カタログHTMLに落とす。特定スライドの構図・ロゴ・写真・固有コピーは持ち込まない。`board.html`・`inbox/` は社内閲覧専用（公開しない）。
※ 自動巡回（スクレイピング）はしない・できない。スクショは手動で `inbox/` に置き、必要なら私が画像を見て原則を抽出する。

## 蒸留チェックリスト（presets/ に落とすとき何を見るか）

- [ ] **配色**：主色・副色・アクセント・背景・文字の HEX を吸い出す（3〜5色に絞る）
- [ ] **書体**：見出し／本文のペアと、太さ・字間・行間の傾向
- [ ] **余白リズム**：外周マージン、要素間ギャップ、コンテンツ密度（詰める/空ける）
- [ ] **レイアウトの型**：情報の置き方の“考え方”（例：大見出し＋右下小図、左帯＋右本文）
- [ ] **モチーフ**：反復される装飾（角丸/直角、ライン、番号、アイコンの扱い）
- [ ] **グラフ装飾**：軸・グリッド・データラベル・強調色の使い方
- [ ] ⚠️ ブランド固有要素（ロゴ・写真・独自イラスト・固有コピー）は**取り込まない**
